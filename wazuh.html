What we are monitoring

We monitor the Windows machine — specifically its Windows Security Event Logs. The Wazuh Agent reads these automatically and ships them to the Wazuh VM. Wazuh has hundreds of built-in detection rules so alerts fire without writing any rule logic.

Section 03

03 Installation Instructions

Part A — Wazuh Server (VirtualBox OVA)
1Install VirtualBox

Download and run the VirtualBox installer for Windows hosts. Accept all defaults during installation. Restart Windows if prompted.

⚠️
Enable hardware virtualisation first

If VirtualBox shows an error about virtualisation not being enabled, restart your PC, enter BIOS/UEFI settings, and enable Intel VT-x or AMD-V. The option is usually under Advanced CPU settings.

2Download and Import the Wazuh OVA

Download the OVA file from the link in Section 02. It is approximately 4 GB — this will take a few minutes.

Once downloaded, import it into VirtualBox:

🖱️
Import steps in VirtualBox

File → Import Appliance → browse to the downloaded wazuh-4.14.4.ova file → Next → Import

The import takes 2–5 minutes. Leave all settings at their defaults during import.

⚠️
Critical VirtualBox setting — set this before starting the VM

After import, select the VM → Settings → Display → Graphics Controller → change to VMSVGA. Using any other controller will freeze the VM window.

3Configure VM Network — Bridged Adapter

The Wazuh VM must be on the same network as your Windows machine so the agent can reach it. Set the network adapter to Bridged:

🖱️
In VirtualBox

Select the Wazuh VM → Settings → Network → Adapter 1 → Attached to: Bridged Adapter → Name: select your active Windows network adapter → OK

4Start the VM and Get Its IP Address

Click Start in VirtualBox to boot the Wazuh VM. Wait for the boot to complete (1–2 minutes) until you see the login prompt.

Log in to the VM console with these credentials:

Wazuh VM — console login credentials
Username: wazuh-user
Password: wazuh

Once logged in, get the VM's IP address — you need this for the agent and the dashboard:

Wazuh VM — console
ip addr show | grep "inet " | grep -v 127.0.0.1

Note the IP shown (e.g. 192.168.x.x). This is your Wazuh Server IP — write it down. You will use it in the agent installation and to access the dashboard.

5Open the Wazuh Dashboard

On your Windows machine, open a browser and navigate to the Wazuh VM's IP address:

Browser — replace with your Wazuh VM IP
https://192.168.x.x

Your browser will show a certificate warning — click Advanced → Proceed. This is expected for the self-signed lab certificate.

Wazuh Dashboard — default login credentials
Username: admin
Password: admin
✅
Wazuh dashboard is working when

You see the Wazuh home screen with the Overview panel. It will show 0 agents connected — that is correct at this stage. The agent comes next.

Part B — Wazuh Agent (Windows)
6Install the Wazuh Agent on Windows

Open PowerShell as Administrator and run the silent install. Replace 192.168.x.x with your Wazuh VM IP from Step 4:

PowerShell — Run as Administrator
# Install the agent — replace 192.168.x.x with your Wazuh VM IP
msiexec.exe /i wazuh-agent-4.9.2-1.msi /q `
  WAZUH_MANAGER="192.168.x.x" `
  WAZUH_AGENT_NAME="Windows-Lab"

Start the agent service:

PowerShell — Run as Administrator
NET START WazuhSvc

Verify it is running:

PowerShell — Verify
Get-Service WazuhSvc
✅
Verify the agent appears in the dashboard

Go to Wazuh Dashboard → Agents. You should see Windows-Lab listed with status Active within 1–2 minutes. Windows Security Events will begin flowing immediately once the agent connects.

Part C — Attacker Machine (Kali WSL2)
7Install Attack Tools on Kali

Open your Kali WSL2 terminal. This is the only thing installed on Kali for this lab:

Kali Linux — WSL2 Terminal
sudo apt update && sudo apt install -y nmap hydra
8Find Your Windows Host IP from Kali

Every attack command targets the Windows machine IP. Get it from Kali:

Kali Linux — WSL2 Terminal
cat /etc/resolv.conf | grep nameserver

The IP shown (usually 172.x.x.x) is your Windows host. Write it down — every attack command uses this IP.

📝
Two different IPs in this lab

Wazuh VM IP (Step 4, e.g. 192.168.x.x) — used when installing the agent and accessing the dashboard.

Windows host IP (Step 8, e.g. 172.x.x.x) — used as the attack target in hydra and nmap commands.

Section 05

05 Complete Uninstall

Run through these steps after your test run to get back to a clean slate. Once done, the machine will be in exactly the same state as before — ready to redo the lab in class.

⚠️
Run in order

Stop the agent before uninstalling it, and power off the VM before deleting it. Skipping the stop steps can leave orphaned processes.

Step 1 — Stop and Uninstall the Wazuh Agent (Windows)
PowerShell — Run as Administrator
# Stop the agent service
NET STOP WazuhSvc

# Uninstall the agent via MSI — finds and removes it automatically
$agent = Get-WmiObject -Class Win32_Product | Where-Object { $_.Name -like "*Wazuh Agent*" }
if ($agent) {
    msiexec.exe /x $agent.IdentifyingNumber /qn /norestart
    Write-Host "Wazuh Agent removed."
} else {
    Write-Host "Wazuh Agent not found."
}

Or uninstall manually: Settings → Apps → search "Wazuh" → Wazuh Agent → Uninstall

Step 2 — Delete Leftover Agent Files (Windows)
PowerShell — Run as Administrator
# Remove agent installation folder
Remove-Item -Path "C:\Program Files (x86)\ossec-agent" -Recurse -Force -ErrorAction SilentlyContinue

# Confirm it is gone
Test-Path "C:\Program Files (x86)\ossec-agent"
# Should return: False
Step 3 — Remove the Wazuh VM (VirtualBox)
🖱️
In VirtualBox

1. Right-click the Wazuh VM in the list → Close → Power Off (if it is running)

2. Right-click the VM → Remove → Delete all files

This deletes the VM and all its disk files. The OVA download file itself is kept — you can reimport it for the next session without re-downloading.

Step 4 — Verify Clean State (Windows)
PowerShell — Run as Administrator
# Check agent service is gone — should return an error
Get-Service WazuhSvc -ErrorAction SilentlyContinue

# Check agent folder is gone — should return False
Test-Path "C:\Program Files (x86)\ossec-agent"
✅
Clean state confirmed when

Get-Service returns nothing (or "not found") and Test-Path returns False. The VM is deleted in VirtualBox. The machine is back to its original state.

Step 5 — Kali Cleanup (Optional)
Kali Linux — WSL2 Terminal
# Remove attack tools if you want a fully clean attacker machine
sudo apt remove -y nmap hydra && sudo apt autoremove -y
